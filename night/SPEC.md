## Кейс (дословно)
BUSINESS: Как повысить эффективность работы торговой команды?

Вы являетесь командой приглашённых специалистов, работающая с производственной
компанией, которая выпускает молочную продукцию. Компания сотрудничает с торговыми
точками через сеть торговых представителей, однако в последнее время столкнулась
с проблемами контроля продаж и эффективности сотрудников.

Текущая ситуация:
1. Торговый представитель не посетил 5 запланированных торговых точек.
2. Продажи одного из сотрудников упали на 30% по сравнению с предыдущим периодом.
3. В одной из торговых точек отсутствует морозильный ларь компании.
4. В торговой точке установлен морозильник, но продажи продукции отсутствуют.
5. Один из сотрудников выполняет только 50% установленного плана продаж.

Задача: разработать систему, которая поможет компании контролировать работу торговых
представителей, выявлять проблемы в торговых точках и повышать эффективность продаж.

Ограничения: бюджет 30 млн ₸; срок реализации 6 месяцев; система должна
**автоматически фиксировать отклонения, выявлять возможные причины проблем и
своевременно уведомлять руководство**.

## Критерии жюри (по 0–5, итого 25)
1. Инновационность идеи. 2. Функциональность и расчёты (для бизнес-кейса — финмодель;
работают ли основные функции, понятно ли, откуда цифры). 3. Практическая значимость и
реалистичность бюджета (укладывается ли в 30 млн ₸ и 6 мес.) — **решает при равенстве баллов**.
4. Презентация (понятно, по порядку, в регламент). 5. Работа команды и ответы на вопросы.
5 баллов = «выводы подтверждены цифрами или работающим демо».

## Решения, принятые с владельцем (не пересматривать)
- Продукт: **веб-приложение на Next.js (TypeScript, App Router)** + **финмодель в Excel (.xlsx)**.
- Деплой на **Vercel** (CLI уже залогинен) — ссылка для жюри и для записи видео.
  Приложение должно также запускаться локально по README без интернета-зависимостей
  (никаких внешних API/ключей во время работы; демо-данные внутри репозитория).
- Без LLM/внешних AI API (ключей нет): причины отклонений выводятся правилами.
- Документация и презентация — **черновики в Markdown** в `docs/`; оформляют люди.
- Название проекта придумать самим; имена участников — заглушки `[Участник N]`,
  название команды — `[Название команды]`.
- Язык интерфейса, документации и материалов — **русский**. Валюта — ₸.

## Что должно работать (MVP, демо-путь)
1. **Демо-данные** (детерминированные, генерируются скриптом или лежат в JSON):
   ~10–15 торговых представителей, ~100+ торговых точек, план/факт продаж по периодам,
   плановые и фактические визиты (с GPS-отметкой/временем), холодильное оборудование
   компании по точкам. В данных обязательно присутствуют **все 5 ситуаций из кейса**.
2. **Движок отклонений** (чистые функции, покрыты unit-тестами) автоматически находит
   как минимум эти 5 типов: пропущенные плановые визиты; падение продаж сотрудника
   ≥ 30% к прошлому периоду; точка без морозильного ларя компании; ларь установлен,
   но продаж нет; выполнение плана ≤ 50%. Пороги — в конфиге.
3. **Возможные причины**: для каждого отклонения правила сопоставляют связанные данные
   (например, падение продаж + пропуски визитов → «снизилась частота визитов»;
   ларь без продаж → «нет поставок / ларь не используется под нашу продукцию / точка
   закрыта» и т.п.) и показывают причины с обоснованием из данных и рекомендуемым
   действием.
4. **Уведомления руководству**: лента алертов в приложении по критичности + симуляция
   отправки (Telegram/e-mail) с текстом сообщения, без реальных токенов.
5. **Экраны**: дашборд руководителя (KPI, алерты), карточка сотрудника, карточка точки,
   список отклонений с фильтрами. Понятно с первого взгляда, хорошо смотрится на видео.
6. **Финмодель** `finance/financial-model.xlsx` с живыми формулами (не просто числа):
   CAPEX/OPEX внедрения в пределах **30 млн ₸ за 6 мес.** (разбивка по статьям и месяцам),
   допущения отдельным листом, ожидаемый эффект (рост продаж, снижение потерь),
   ROI / окупаемость, сценарии (пессимистичный/базовый/оптимистичный). Скрипт генерации
   в репозитории; цифры в документации совпадают с таблицей. Желательно — страница
   с финмоделью и в веб-приложении.
